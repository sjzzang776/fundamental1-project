## 1. 무엇을 만드는가

패스트푸드점 **음성 + 터치 주문 키오스크**의 화면 디자인을 Figma에 새 파일로 만든다.

- 문제: 기존 키오스크는 기계에 익숙하지 않은 사람(60대 이상, 디지털 문맹)이 쓰기 어렵다.
- 해결: 대화형 에이전트가 **음성으로 안내**하고, 사용자는 **말하기와 버튼 누르기 중 편한 쪽**을 언제든 고른다.
- 핵심 원칙: **모든 화면에 음성 안내 문장(자막)과 선택지 버튼이 항상 함께 보인다.** 음성이 실패해도 화면만으로 끝까지 주문할 수 있어야 한다.

## 2. 사용자와 접근성 규칙 (가장 중요, 모든 화면에 적용)

주 사용자: 패스트푸드점 손님, 특히 **60대 이상·디지털 문맹**. 일반 사용자도 함께 쓴다.

| 규칙 | 기준 |
|---|---|
| 큰 글씨 | 본문 최소 32px, 버튼 글씨 최소 40px, 가격·주문번호 등 핵심 숫자 64px 이상 (1080px 폭 기준) |
| 뚜렷한 대비 | 글자와 배경 명도 대비 7:1 이상 (WCAG AAA). 연회색 글씨 금지 |
| 선택지 수 | 한 화면에 고를 수 있는 버튼 **최대 3~4개** |
| 큰 버튼 | 높이 최소 120px, 버튼 사이 간격 최소 24px, 화면 아래쪽 2/3 안에 배치 (손이 닿기 쉬운 곳) |
| 쉬운 말 | 외래어·전문용어 대신 쉬운 말. 예: "테이크아웃" → "포장", "옵션" → "고르기", "결제 수단" → "어떻게 내실래요?" |
| 색에만 의존 금지 | 상태는 색 + 아이콘 + 글자로 함께 표시 |
| 한 번에 하나 | 한 화면에서 질문 하나만 한다 (세트/음료/사이즈를 한 화면에 섞지 않음) |
| 항상 있는 탈출구 | 모든 화면 하단에 **[처음으로] [취소] [직원 부르기]** 고정 |

## 3. 화면 규격과 공통 레이아웃

- 프레임 크기: **세로형 키오스크 1080 × 1920**
- 주방 화면만 **가로형 1920 × 1080**
- 모든 화면은 같은 골격을 쓴다 (위에서 아래로):

| 영역 | 내용 |
|---|---|
| ① 진행 표시 | 지금 몇 번째 단계인지 (예: "2 / 6 메뉴 고르기"). 숫자 + 막대 |
| ② 에이전트 말풍선 | 에이전트 캐릭터(단순한 아이콘) + 지금 읽어 주는 안내 문장을 자막으로 크게 표시 |
| ③ 음성 상태 | 마이크 아이콘과 상태 글자: "듣고 있어요" / "말하는 중" / "잠시만요". 상태별 variant |
| ④ 본문 | 메뉴 사진, 장바구니 등 그 단계의 내용 |
| ⑤ 선택지 버튼 | 지금 고를 수 있는 버튼 2~4개, 크게 |
| ⑥ 하단 고정 바 | [처음으로] [취소] [직원 부르기] |

## 5. 디자인 시스템 (Page: `00 Design System`)

먼저 이것부터 만들고, 모든 화면은 여기의 **변수(Variables)와 컴포넌트**만 써서 조립한다.

**변수 (Variables)**
- 색: `bg`, `surface`, `text-primary`, `text-secondary`, `primary`(주요 버튼), `primary-text`, `danger`, `success`, `focus`(빛나는 안내 영역). 밝은 배경 + 진한 글씨 기준, 대비 7:1 이상
- 글자 크기: `display`(96), `title`(56), `button`(40), `body`(32), `caption`(28). 글꼴은 한글 가독성이 좋은 산세리프 (예: Pretendard, 없으면 Noto Sans KR)
- 간격: 8의 배수 (8, 16, 24, 32, 48, 64)
- 모서리: `radius-md` 16, `radius-lg` 24

**컴포넌트 (variant 포함)**
| 컴포넌트 | variant |
|---|---|
| `Button` | type: primary / secondary / danger · state: default / pressed / disabled |
| `ChoiceButton` | 아이콘 + 큰 글자. 선택지용 |
| `MenuCard` | 사진, 메뉴 이름, 가격. state: default / selected |
| `AgentBubble` | 캐릭터 + 자막. state: speaking / listening / thinking |
| `MicIndicator` | listening / speaking / idle / error |
| `ProgressBar` | step 1~6 |
| `CartItem` | 이름, 수량, 가격, [빼기] [하나 더] |
| `BottomBar` | [처음으로] [취소] [직원 부르기] |
| `Modal` | 예외 안내용. 제목, 문장, 버튼 2~3개 |
| `GuideAnimation` | barcode / card. 화면 아래쪽을 가리키는 화살표 + 기기 그림 |

## 6. 작업 방식 (에이전트가 지킬 것)

1. **새 Figma 파일**을 만든다. 파일 이름: `Fundamental 1 · 음성 주문 키오스크 UI`
2. 페이지를 `00 Design System` → `01 Main Flow` → `02 Exceptions` → `03 Store Screens` 순서로 만든다.
3. 디자인 시스템을 먼저 완성한 뒤 화면을 조립한다. 화면에서 색·글자 크기를 직접 입력하지 않는다.
4. 모든 레이아웃은 **Auto Layout**으로 만든다 (코드의 flex로 그대로 옮기기 위함).
5. 레이어 이름은 의미 있는 영어로 짓는다 (`Frame 123` 같은 이름 금지). 예: `agent-bubble`, `choice-list`, `cart-total`
6. 기본 흐름 화면은 프레임을 왼쪽에서 오른쪽으로 순서대로 놓고, 화면 사이를 **프로토타입 연결**(버튼 클릭 → 다음 화면)로 잇는다. 흐름은 아래와 같다.
   ```
   대기 → 식사 장소 → 메뉴 추천·선택 → 옵션(세트 → 음료 → 크기) → 주문 확인
   주문 확인 --수정·추가--> 메뉴 추천·선택
   주문 확인 --맞아요--> 쿠폰 묻기 --있어요--> 바코드 스캔 → 할인 적용 → 결제
                                  --없어요--> 결제
   결제 --실패--> 결제 실패(다시 시도 / 직원 호출)
   결제 --성공--> 주문 완료 → (매장) 호출 화면
   ```
7. 작업이 끝나면 다음을 보고한다.
   - 파일 링크와 각 페이지·프레임의 링크 목록
   - 만든 컴포넌트와 변수 목록
   - 기획서에 없어서 임의로 정한 것 (위치, 문구, 크기 등)

## 7. 하지 말 것

- **실제 브랜드 사용 금지:** 메뉴 기준은 맥도날드 코리아지만, 로고·브랜드 이름·실제 상품 사진·브랜드 색을 쓰지 않는다. 가게 이름은 `○○버거`, 메뉴 사진은 회색 자리표시(placeholder) + 메뉴 이름으로 둔다.
- 메뉴 이름·가격을 지어내지 않는다. 예시 문장에 나온 "불고기버거 세트 7,500원", "콜라"만 쓰고, 나머지는 `메뉴 이름`, `0,000원` 같은 자리표시로 둔다. 메뉴 목록은 기획 담당이 나중에 추가한다.
- 한 화면에 선택지를 5개 이상 두지 않는다. 작은 글씨, 연한 색 글씨, 아이콘만 있는 버튼을 쓰지 않는다.
- 위 목록에 없는 기능(회원가입, 포인트 적립, 다국어 등)을 추가하지 않는다.

## 8. 아직 정해지지 않은 것 (임의로 확정하지 말고 자리만 비워 둘 것)

- 바코드 스캔 장치: 키오스크 스캐너인지 시연용 웹캠인지 → `05b-coupon-scan` 의 안내 그림은 "화면 아래쪽"으로 두되, 웹캠 버전 variant도 하나 만든다.
- 번호표 출력 기기 포함 여부 → `07-order-complete` 에 "번호표를 받아 가세요" 문구를 별도 레이어로 두어 끄고 켤 수 있게 한다.
- 결제 수단: MVP는 카드만. 다른 수단 버튼은 비활성(disabled) 상태로만 둔다.
- 와이어프레임이 확정되면 기획서 5-4 항목에 이 Figma 파일 링크를 붙인다 (사람이 할 일).
