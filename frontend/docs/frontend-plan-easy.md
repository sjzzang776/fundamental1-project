# 프론트엔드 작업 계획서 (쉬운 버전)

> 작성일: 2026-10-19 · 담당: 프론트엔드
> 더 자세한 내용(API 이름, 화면별 표)은 [frontend-plan.md](frontend-plan.md)에 있어요.

---

## 먼저 알아 두기: 우리가 만드는 것

할머니, 할아버지도 쉽게 쓸 수 있는 **햄버거 가게 주문 기계(키오스크)** 를 만들어요.
손님은 **말로 해도 되고, 버튼을 눌러도 돼요.**

우리 팀은 이렇게 일을 나눠요.

| 누가 | 하는 일 | 비유 |
|---|---|---|
| 프론트엔드 (나) | 손님이 보는 **화면**을 만들어요 | 가게의 **카운터와 메뉴판** |
| 백엔드 (Gilbert 님) | 주문을 기억하고 계산하는 **서버**를 만들어요 | 가게 안쪽의 **계산 담당 직원** |
| 모델 구축 | 손님 말을 알아듣는 **AI**를 만들어요 | 말을 받아 적는 **귀** |

화면은 직접 계산하지 않아요. 손님이 무언가를 하면 서버에 **"손님이 이거 눌렀어요!"** 라고 알려 주고,
서버가 **"다음엔 이 말과 이 버튼을 보여 주세요"** 라고 답하면 그대로 보여 줘요.

## 전체 순서 한눈에 보기

```
0. 준비하기 → 1. 뼈대 만들기 → 2. 주문 화면 → 3. 쿠폰·결제 화면
→ 4. 곤란한 상황 대비 → 5. 말로 주문하기 → 6. 가게 직원용 화면 → 7. 마지막 점검
```

## 0단계. 준비하기

**무엇을 하나요?**
- 팀원들이 GitHub에 올린 최신 내용을 내 컴퓨터로 가져와요.
- 우리 프로그램 전체를 내 컴퓨터에서 켜 봐요. (Docker Desktop을 켜고 `docker compose up --build`)
- 서버 설명서 페이지(`http://localhost:8000/docs`)에서 버튼을 눌러 주문을 한 번 해 봐요.
- 백엔드 담당자에게 궁금한 점 4가지를 물어봐요.

**왜 하나요?**
- 요리하기 전에 재료와 조리 도구를 먼저 챙기는 것과 같아요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 내 컴퓨터에서 우리 프로그램이 켜져요.
- ✅ 서버가 어떻게 대답하는지 눈으로 확인했어요.
- ✅ 궁금한 점에 대한 답을 받았어요.

## 1단계. 뼈대 만들기

**무엇을 하나요?**
- 화면이 서버와 이야기하는 **전화기 역할 코드**를 만들어요.
- Figma에 그려 둔 **부품 10개**(큰 버튼, 말풍선, 장바구니 줄, 아래쪽 고정 버튼 등)를 코드로 만들어요.
- 모든 화면이 함께 쓰는 **틀**을 만들어요. 위에서부터 차례로 이렇게 놓여요.

```
[ 지금 몇 번째 단계인지 ]
[ 안내 말풍선 ]
[ 마이크 상태 ]
[ 메뉴 사진이나 장바구니 ]
[ 고를 수 있는 큰 버튼 2~4개 ]
[ 처음으로 | 취소 | 직원 부르기 ]
```

**왜 하나요?**
- 레고 블록을 먼저 만들어 두면 집(화면)을 빨리, 똑같은 모양으로 지을 수 있어요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 아직 내용은 없지만, 키오스크 모양의 빈 화면이 떠요.
- ✅ 글씨가 크고 버튼도 커요. 할머니도 누르기 쉬워요.

---

## 2단계. 주문 화면 만들기 (버튼만으로)

**무엇을 하나요?**
- 이 순서대로 화면을 이어 붙여요.

```
처음 화면 [주문 시작]
→ "드시고 가세요, 포장하세요?" [매장에서] [포장]
→ "어떤 걸 드시고 싶으세요?" 추천 메뉴 3개 (사진 + 가격)
→ "세트로 드릴까요?" [세트] [단품]
→ "음료는 뭐로 드릴까요?" (음료 5개라 2쪽으로 나눔)
→ "사이즈는요?" [미디엄] [라지]
→ "빅맥 세트 하나, 모두 7,200원이에요. 맞으세요?" [맞아요] [수정할게요]
```

- 버튼을 누르면 버튼에 쓰인 글자를 그대로 서버에 보내요. 서버가 다음에 보여 줄 말과 버튼을 알려 줘요.
- 음료는 5개라서 한 화면에 다 넣으면 너무 많아요. 그래서 **1쪽에 3개 + [다른 음료 보기]**, **2쪽에 2개 + [앞으로]** 로 나눠요.

**왜 하나요?**
- 주문 기계에서 가장 중요한 일이 **메뉴를 고르고 담는 것**이기 때문이에요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 버튼만 눌러서 "빅맥 세트"를 장바구니에 담을 수 있어요.
- ✅ 장바구니 화면에서 [빼기] [하나 더] 를 누르면 수량이 바뀌고, 금액도 서버가 다시 계산해 줘요.

## 3단계. 쿠폰·결제·주문번호 화면 만들기

**무엇을 하나요?**
- **쿠폰:** "앱 쿠폰 있으세요?" → [쿠폰 있어요] 를 누르면 바코드 대는 곳을 화살표 그림으로 알려 줘요.
  바코드 기계가 읽은 숫자를 서버에 보내요.
- **결제:** [카드 결제] 를 누르면 "카드를 꽂아 주세요" 그림이 나와요.
  진짜 카드 기계가 아직 없어서, 연습용 **[결제 성공] [결제 실패]** 버튼으로 흉내 내요.
- **주문번호:** 결제가 되면 **"주문번호 1번"** 을 화면에 아주 크게 보여 주고, 10초 뒤 처음 화면으로 돌아가요.

**왜 하나요?**
- 메뉴를 골랐으면 돈을 내고 번호표를 받아야 주문이 끝나니까요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 연습용 쿠폰 5장을 하나씩 대 보면 각각 알맞은 안내가 나와요.
  - TEST0001 → "1,000원 할인돼요"
  - TEST0004 → "기간이 끝난 쿠폰이에요"
  - TEST0005 → "이미 사용한 쿠폰이에요"
- ✅ [결제 성공] → 주문번호가 크게 떠요.
- ✅ [결제 실패] → "결제가 안 됐어요. 다시 해 볼까요?" 가 떠요.

## 4단계. 곤란한 상황 대비하기

**무엇을 하나요?**

| 이럴 때 | 화면은 이렇게 해요 |
|---|---|
| 손님이 15초 동안 아무것도 안 함 | "도움이 필요하세요?" 를 물어봐요 |
| 그 뒤로 15초 더 아무것도 안 함 | 장바구니를 비우고 처음 화면으로 돌아가요 (결제 중일 때는 안 돌아가요) |
| [처음으로] 누름 | 맨 처음 질문으로 돌아가요 |
| [취소] 누름 | "정말 취소할까요?" 한 번 더 묻고 취소해요 |
| [직원 부르기] 누름 | "직원을 불렀어요. 잠시만 기다려 주세요." |
| 말을 못 알아들음 | "다시 한번 말씀해 주세요. 버튼을 눌러도 돼요." |
| 인터넷이 잠깐 끊김 | 한 번 더 시도하고, 그래도 안 되면 직원을 부르라고 알려 줘요 |

**왜 하나요?**
- 할머니, 할아버지가 헷갈리거나 멈춰 있어도 **절대 막히지 않게** 하려고요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 화면을 30초 동안 가만히 두면 처음 화면으로 돌아가요.
- ✅ 어느 화면에서든 아래쪽 버튼 3개가 잘 동작해요.

## 5단계. 말로 주문하기

**무엇을 하나요?**
- 마이크로 손님 말을 녹음해서(최대 15초) 서버에 보내요.
- 서버가 알아들은 말을 "이렇게 들었어요: 불고기버거 세트 하나" 처럼 화면에 잠깐 보여 줘요.
- 안내 문장을 소리 내어 읽어 줘요. 우리 팀의 음성 기능이 아직 준비 중이라, 그동안은 **인터넷 브라우저에 들어 있는 읽어 주기 기능**을 빌려 써요.
- 마이크 그림 옆에 "듣고 있어요 / 말하는 중 / 잠시만요" 를 보여 줘요.

**왜 하나요?**
- 버튼 누르기가 어려운 분도 **말만으로** 주문할 수 있게 하려고요. 이게 우리 키오스크의 가장 큰 장점이에요.

**다 하면 어떻게 되나요? (결과)**
- ✅ "불고기버거 세트 하나 줘" 라고 말하면 장바구니에 담겨요.
- ✅ 음성 기능이 고장 나도 버튼으로는 끝까지 주문할 수 있어요.

---

## 6단계. 가게 직원용 화면 만들기

**무엇을 하나요?**
- **호출 화면** (가게 벽에 거는 큰 TV): "준비 중 번호" 와 "음식 나온 번호" 를 보여 줘요. 3초마다 새로 확인해요.
- **주방 화면**: 결제된 주문 목록을 보여 주고, 요리가 끝나면 [완료] 를 눌러요.
- **직원 호출 알림**: 손님이 [직원 부르기] 를 누르면 주방 화면 위쪽에 "키오스크 1번에서 불렀어요" 가 떠요.

**왜 하나요?**
- 손님이 주문만 하고 끝나는 게 아니라, **음식을 받아야** 진짜 끝이니까요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 키오스크에서 결제 → 주방 화면에 주문이 떠요 → [완료] 누름 → 호출 화면에 번호가 떠요.

## 7단계. 마지막 점검하고 올리기

**무엇을 하나요?**
- 기획서에 적힌 규칙을 하나씩 확인해요.
  - 글씨가 충분히 큰가요?
  - 글자와 배경 색이 확실히 구분되나요?
  - 버튼이 손가락으로 누르기 쉬운 크기인가요?
  - 한 화면에 고를 것이 4개 이하인가요?
- 기획서의 "기본 흐름" 과 "곤란한 상황" 표를 처음부터 끝까지 직접 눌러 봐요.
- GitHub에 올리고 팀원들에게 확인을 받아요.

**왜 하나요?**
- 숙제를 다 하고 나서 틀린 곳이 없는지 다시 보는 것과 같아요.

**다 하면 어떻게 되나요? (결과)**
- ✅ 처음부터 끝까지 막힘없이 주문되는 키오스크 화면이 완성돼요.
- ✅ 팀원 모두가 GitHub에서 결과를 볼 수 있어요.
