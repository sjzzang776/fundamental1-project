# 기획 결정 기록

기획에서 정한 주문 흐름·화면 규칙을 날짜순으로 적는다. 백엔드·프론트는 이 기록을 기준으로 만든다.
노션 기획서에도 같은 내용을 반영한다.

---

## 2026-10-19 · 세트 사이드는 묻지 않는다

- **결정:** 세트 주문에서 사이드는 따로 묻지 않고 **후렌치 후라이**를 기본으로 넣는다.
  주문 순서는 지금처럼 `세트/단품 → 음료 → 사이즈` 를 유지한다.
- **이유:** 어르신 손님이 덜 지치도록 질문 수를 줄인다. 대부분 기본 사이드를 고른다.
- **보완 (함께 요청):**
  1. 세트 옵션을 고르는 중에 사이드 이름을 말하면("너겟으로 주세요", "감자튀김이요") **단품으로 따로 담지 않고 세트 사이드로 처리**한다.
     같은 규칙을 음료에도 적용한다("콜라 제로로 주세요" → 세트 음료). — 백엔드 (PR #7, #8에서 알린 문제)
  2. 주문 확인 화면에 `사이드: 후렌치 후라이 [바꾸기]` 를 보여 주고, 버튼으로 맥너겟 4조각(+500원)·치즈스틱 2조각(+500원)으로 바꿀 수 있게 한다. — 프론트·백엔드
- **관련:** PR #4 "다음 작업자를 위한 메모"(세트 사이드 기본값), `backend/app/seed.py` 세트 사이드 옵션 3개

## 2026-10-19 · 선택 버튼은 한 화면 최대 4개, 넘치면 쪽 나누기

- **결정:** 프론트 제안(`frontend/docs/frontend-plan.md` 2번 표 3번)을 그대로 채택한다.
  한 화면의 선택 버튼은 **최대 4칸**, 넘치면 다음 쪽으로 나눈다.
- **세트 음료 화면:**
  ```
  1쪽: [코카콜라] [코카콜라 제로] [스프라이트] [다른 음료 보기 ▶]
  2쪽: [아메리카노] [오렌지 주스 +700원] [◀ 처음 음료]
  ```
- 말로는 쪽과 상관없이 5개 모두 언제든 고를 수 있다.
- 선택지가 5개 이상인 **모든 화면**에 같은 규칙을 적용한다.
- **이유:** 메뉴를 줄이지 않고 "한 화면 3~4개" 규칙을 지킨다. 메뉴가 늘어도 같은 규칙으로 해결된다.
- **관련:** PR #4 "다른 파트 영향", PR #9 "확인 방법"(기획 확인 요청)
